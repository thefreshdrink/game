# Ассеты игры: как это устроено и как править руками

Инструкция для человека, а не для агента. Отвечает на четыре вопроса:
что такое PixelLab и MCP, где лежат файлы, какая сетка, и что можно
сделать самому без единой генерации.

---

## 1. Что такое MCP и PixelLab простыми словами

**PixelLab** — сервис, который рисует пиксель-арт по описанию. У него есть
сайт, а есть программный доступ.

**MCP** — способ, которым внешний сервис даёт агенту набор кнопок. Никакой
магии: PixelLab объявляет список инструментов («создать картинку»,
«создать персонажа», «почистить пиксели»), а агент их нажимает и получает
ответ. Ключ доступа лежит в настройках Claude, в переписку он не попадает.

**Как идёт один заказ:**

1. агент зовёт инструмент и сразу получает `job_id` — работа встала в
   очередь на стороне сервиса;
2. агент периодически спрашивает статус (`get_image`);
3. когда готово, приходят ссылки на PNG — их надо **скачать сразу**:
   картинки хранятся **8 часов**, потом пропадают (у нас так уже протухла
   одна партия);
4. агент кладёт файл в проект и приводит к канону локальными скриптами.

**Деньги.** Счёт в «генерациях», у подписки 2000 в месяц (обновление
4 октября). Цена зависит от инструмента, а не от числа вариантов:

| инструмент | цена | что даёт |
|---|---|---|
| `create_image_pro` | **20** | качество; число вариантов за тот же счёт зависит от холста |
| `create_image_pixflux` / `pixen` | **1** | быстрый черновик, стиль не держит |
| `create_character_state` | 20–40 | вариация существующего персонажа (так сделаны портреты карт) |
| `create_sidescroller_tileset` | 2–3 | тайлсет платформера |
| `unzoom_image`, `correct_pixelart`, `reduce_colors` | 0.1 | чистка; у нас это делают свои скрипты бесплатно |

**Ключевая экономия.** Один вызов `create_image_pro` стоит 20 генераций
независимо от того, вернёт он 1 вариант или 64. Сколько вернёт — решает
размер холста:

| холст | вариантов за один вызов |
|---|---|
| до 42 px | **64** |
| до 85 px | **16** |
| до 170 px | 4 |
| больше | 1 |

Поэтому просить картинку 192×256 — это 20 генераций за один-единственный
вариант, а 64×52 — те же 20 за шестнадцать.

## 2. Где лежат файлы

| место | что там |
|---|---|
| `public/assets/<папка>/*.png` | **то, что видит игра**. Только эти файлы попадают в сборку |
| `src/main.js`, список `IMAGE_MANIFEST` | какой файл под каким именем грузится |
| `art-source/` | исходники и черновики, в игру не идут |
| `ASSETS.md` | таблица: файл, размер, масштаб, где используется |
| `tools/*.py` | скрипты приведения к канону и проверки |
| `../design-system/tarot-journey.hex` | палитра для Aseprite / Pixelorama |

Чтобы новый файл появился в игре, мало положить PNG — нужна строка в
`IMAGE_MANIFEST`. Без неё картинка просто не загрузится.

## 3. Сетка: главное, что нужно знать

Игра рисует на холсте **430×932** условных пикселя и растягивает его под
экран целым числом раз. Отсюда закон:

> **1 пиксель арта = 2 пикселя экрана.** Портреты карт — исключение,
> у них 1 к 4.

Практически это значит: спрайт 64×52 занимает на экране 128×104, а
спрайт 32×26 при масштабе ×4 — те же 128×104, но зерно вдвое крупнее.
**Размер зерна выбирается масштабом, а не «качеством» генерации.**

Для изометрических брусков Башни сетка такая (в пикселях арта):

| величина | значение | смысл |
|---|---|---|
| шаг вправо | 16 | на одну единицу глубины |
| шаг вниз | 8 | ровно половина — это и есть «2:1» |
| высота ряда | 20 | насколько ряд выше предыдущего |
| брусок 3×1 | **64×52** | и ни пикселем иначе |

Диагональ обязана идти **2 пикселя вбок на 1 вниз**. Если рисовать на
глаз, кладка поедет — именно поэтому силуэт у нас считает скрипт.

## 4. Что вы можете делать руками

### 4.1 Три тона из одного бруска

Не нужно генерировать светлый, серый и тёмный отдельно. Есть один брусок —
остальные получаются сдвигом по палитре:

```bash
cd ~/Downloads/game/tarot-journey
python3 tools/iso-block.py --unit 16 --tone 1  исходник.png public/assets/tower/block_light.png
python3 tools/iso-block.py --unit 16 --tone 0  исходник.png public/assets/tower/block_mid.png
python3 tools/iso-block.py --unit 16 --tone -1 исходник.png public/assets/tower/block_dark.png
```

`--tone 1` — на ступень светлее, `-1` — темнее. Белый контур не трогается,
он роль, а не оттенок. Флаг `--flat` дополнительно делает грани
однотонными, с тенью только по краю — то, что на референсе.

### 4.2 Правка в редакторе

Подходит Aseprite или бесплатная Pixelorama.

1. Откройте PNG из `public/assets/…`.
2. Импортируйте палитру `../design-system/tarot-journey.hex` — тогда мимо
   цветов игры не промахнётесь.
3. Рисуйте **карандашом, не кистью**: никакого сглаживания, никакой
   прозрачности между 0 и 100 %.
4. Сохраняйте в тот же файл, размер не меняйте.

### 4.3 Проверка после правки

```bash
python3 tools/check-asset.py public/assets/tower/block.png
```

Скрипт скажет, что не так: цвет мимо палитры, полупрозрачные пиксели от
сглаживания, нечётный размер, случайно увеличенная картинка. Пока он не
говорит «в порядке» — в игру не ставим.

### 4.4 Посмотреть результат

```bash
npx vite --port 4390 --strictPort
```

и открыть `http://127.0.0.1:4390/` — игра подхватит новые файлы сразу.

## 5. Разные устройства

Игра живёт на холсте 430×932 и масштабируется под экран. Что из этого
следует для арта:

- **Ассеты делаются один раз, в маленьком нативном размере**, и
  увеличиваются целыми числами. Наборов «@2x / @3x», как в обычных
  приложениях, здесь не нужно.
- **Дробный масштаб запрещён.** Он превращает пиксель-арт в кашу. Код
  везде округляет до целого, поэтому на любом айфоне и андроиде картинка
  остаётся резкой, а разницу экранов съедают поля по краям.
- Поэтому же **размеры спрайтов чётные**: при ×2 нечётный размер даёт
  полупиксельную кромку.
- Для упаковки в приложение (PWA или оболочка вроде Capacitor) ассеты
  менять не придётся — меняется только оболочка вокруг того же холста.

## 6. Навык для Клода: что в нём должно быть

Чтобы следующая сессия не начиналась с нуля, имеет смысл собрать навык —
папку с инструкцией и скриптами, которую агент подхватывает сам. Внутри:

1. **Спека ассета** — короткая форма: экранный размер, арт-размер,
   масштаб, роли тонов, что плоское, а что с деталью.
2. **Рецепты промптов** с параметрами, которые уже сработали: размер
   холста под нужное число вариантов, ссылка на образец стиля, сид.
3. **Скрипты**: посадка на сетку (`iso-block.py`), проверка
   (`check-asset.py`), сборка контактного листа.
4. **Правило показа**: предмет всегда показывается человеку в сборке —
   в кладке, на сцене, — а не только крупно.
5. **Правило экономии**: один якорь стиля на семейство, остальное
   выводится локально; повторная генерация только если якорь отвергнут.

Первые три пункта уже существуют в этом репозитории, навык их только
свяжет.
