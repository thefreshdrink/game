## 2026-08-28 — BUILD-SPEC-03 задача 2: фикс-масштаб спрайтов; высота плиты 24→32

**Убран `uiScale` из размеров всех спрайтов.** Было: всё × `clamp(ширина/430,
0.75..1.25)` — на 390 это 0.907, и 1 арт-пиксель занимал то 1, то 2
экранных (рваный контур). Стало: фиксированный целый множитель.
- Шут/пёс (`leap.js drawPlayer`/`drawDog`): ×2, `PLAYER_W/H`, `DOG_W/H`
  уже удвоены; `sqx/sqy` (squash анимации) остаются.
- Карта (`draw.js`, `reveal.js`, `deck.js` веер): фиксированные
  `CARD_W×CARD_H` = 224×384 везде (общая константа в `cardRender.js`),
  портрет на карте — нативные 164×182. Веер колоды пересчитан под ту же
  карту (рубашки 224, а не `ширина×0.5`) — иначе на переходе 2→3
  выбранная карта скакала бы размером.
- Оракул (`computeOracleLayout`): нативные 430×678 ×1, центр по голове.
  На вьюпортах уже 430 (320/375/390) кончики рогов уходят за край —
  принятый размен спеки, лечится отдельным узким ассетом, не дробным
  масштабом.
- `uiScale` остался только на кеглях текста и отступах.
Проверено покадрово на 320/390/430/1440: прогоны цвета кратны 4 канвас-px
(= 1 арт-px при DPR 2). Аудит всех ассетов манифеста — в `ASSETS.md`.

**Высота видимой плиты дороги 24 → 32 экранных** (16 арт-px = ячейка тайла
целиком). Конфликт доков: `CLAUDE.md` и `design-system §4.5` говорили 24,
переписанная `BUILD-SPEC-03` задача 2 п.4 — «16 арт-px (32 экранных), не

## 2026-08-28 — Мини-игра: ручная ходьба, можно упасть (пересмотр канона)

Правка в чате. Претензия: «фул сам плывёт, надо только перепрыгивать
препятствия, игра очень лёгкая». Решения пользователя по двум развилкам:
прыжок **можно завалить**; после падения — **возврат на начало плиты**
(не рестарт, не экран проигрыша). Плюс: «не жестить со сложностью, плиты
норм размеров»; «платформы разных размеров, но той же высоты (толщины)»;
«собака и персонаж не должны быть за краем плиты».

**Канон.** `CLAUDE.md` «Проиграть нельзя» — оставлен (нет экрана, счёта,
таймера, ретрай бесконечный). «Промахнуться нельзя» из `platforms.js` —
**снято**: помечено в CLAUDE.md как устаревшее. «Темп задаёт игрок» —
теперь буквально (автопрохода нет).

**`leap.js`.**
- Ходьба ручная: `walking` ставится по `pressstart`/`pressend`; в `walk`
  `player.x += PHYS.walk*dt` только если `walking`. Автопрохода и
  авто-«шага через щель» больше нет.
- Состояние `wait_jump` убрано. Прыжок — из `walk`: быстрый свайп (палец
  < 250мс → `swipe`), либо флик вверх на ходу (держал > 250мс → ловим по
  СКОРОСТИ вверх между `holdmove`-событиями, иначе не отличить от дрейфа
  пальца; требует `walking===true`). Слабый ввод — слабый прыжок, щель
  можно не дотянуть.
- Сошёл с края обычной плиты (`player.x > edgeX`) → `air`. Провалился ниже
  `RESPAWN_DROP` → `respawnAtStart()`: на левый край плиты (`p.x+20`),
  `walking=false` (нужен новый тап), короткая вспышка чёрным
  (`respawnFlash`, 0.22с — не полная сцена падения, та отдельная задача 4),
  `deepestY` сброшен (иначе «пустота» снизу кадра остаётся раздутой).
- Последняя плита: у края по-прежнему `wait_leap` → `charge` → удержание →
  `fall` → `prediction`. Ходьба туда упирается в кромку, не сходит.
- Подсказки временные (текст, задача 5 заменит знаками): «HOLD TO WALK»
  пока ни разу не пошёл; «SWIPE TO JUMP» когда в 70px от края не-последней
  плиты.
- Клэмп спрайтов по ОБОИМ краям плиты — и Шут (`drawPlayer`, был только
  правый), и пёс (`drawDog`, не было вовсе; кроме позы `jump` над щелью).
  Пёс в `overtake` целится не в `player.x+30` (за краем), а в
  `lastEdge - DOG_W/2 - 4`.

**`platforms.js`.** 9 плит, все `jump:true`. Ширины 128–224 (минимум 96 не
использую — «норм размеры»), кратны 32. Ступени только ±32. Щели мягкие:
48/56/64 (`G_A/G_B/G_C`) — нормальный свайп берёт с запасом, ступень вниз
можно и шагом. `GAP_JUMP/GAP_JUMP_FAR/GAP_STEP` и «тап гарантированно
перекрывает» — удалены.

**Проверено** в браузере (headless pane тротлит rAF, гнал покадрово):
ручная ходьба (идёт только пока держишь, встаёт — стоит), смена подсказки
у края, сход с края → падение кувырком → возврат на `x=20` со стопом,
клэмп Шута и пса у кромки. `npm run build` чисто, консоль чиста. Прыжок
через щель и финальный leap живьём не гонял (loop тротлится) — код-путь
прежний, ждёт плейтеста на телефоне.

## 2026-08-27 — Каменный тайлсет дороги вместо бруса (внеочередно)

По прямому указанию пользователя, вперёд задачи 2 BUILD-SPEC-03 (та крупнее
и трогает все сцены; здесь — только дорога). Прежний эксперимент с
тайлсетом (`assets/1-bit Pixel Art Platformer Tile.png` → вырезка
`tile_platformer_native.png`) в прошлой сессии был откачен как «грязно
сделано». Пользователь вернул задачу с формулировкой «не создавай, он уже
готов — просто адаптируй»: источником считать этот же лист, не
перерисовывать.

**Что сделано.**

- `design-system/extract-road-tiles.py` (рядом с `build-sprites.py`, вне
  репо) — нарезает из листа три тайла БЕЗ перерисовки: `cap_l` (нативные
  x0..15 y18..29), `mid` (x18..33 y48..59, тайлится), `cap_r` (зеркало
  `cap_l`). Лист — ровный ×2 апскейл 128×128, де-скейл честный. Сквозные
  дырки в швах середины заливаются телом `#232323` из самого листа, чтобы
  плита не просвечивала воздухом. Выход — `public/assets/road/plat_tiles.png`
  (48×12), ноль полупрозрачных пикселей.
- `main.js`: `roadBlock` → `roadTiles: 'assets/road/plat_tiles.png'`.
- `platforms.js`: `drawBlock` (3-slice с растянутой серединой) → `drawRoad`
  — торец 32 + N серединок по 32 + торец 32, каждая копия целая,
  **фиксированный ×2, без `uiScale`** (задача 2 BUILD-SPEC-03: ни одного
  `drawImage` со `* scale`). Проверено покадрово на 390×844: все прогоны
  цвета кратны 4 канвас-px (= 1 арт-px), вертикаль и горизонталь с
  одинаковым шагом. `drawPlatform`/`drawGhostRoad` больше не принимают
  `scale`; заливка `#000000` позади сохранена.
- Ширины плит в `DATA` подогнаны под целое число плиток (кратно 32):
  P1 400→384, средние 108→96, финальная 220→224. Щели (52/64/32) не
  тронуты — пустота не тайлится; сужение плиты только по правому краю,
  приземление всегда у левого края следующей — промахнуться нельзя по
  прежнему построению. `drawGhostRoad` ширина 140→160.
- Дохлые файлы дороги (`frame_block_native.png`, `_source_4x.png`,
  `bar_*`, `cap_*`, `the_frame_block.png`) — из `public/` в
  `art-source/road/` (паттерн уборки из задачи 3).

**Расхождение по палитре — не сглажено.** Тайлсет несёт `#232323` и
`#A0A0A0`, которых нет в палитре CLAUDE.md. Пользователю показаны оба
варианта (faithful / snap-к-палитре); выбран **faithful** — каменный вид
важнее. `--snap` в скрипте остаётся как опция: тело → `#000000`,
`#A0A0A0` → `#B8B8B8`, но камень при этом почти исчезает.

**Расхождение по высоте плиты в доках** (тоже озвучено): CLAUDE.md — 24
экранных, `design-system.md §4.5` — 22 (11 арт-строк), `generation-prompts-
environment.md` — «плита 16 арт-px». Прочитано так: 16 арт-px это ЯЧЕЙКА
тайла, а не видимая плита. Взято 12 нативных × 2 = 24 (CLAUDE.md).
`§4.5` при доработке нужно поправить на +1 строку тела.

**Проверено** на 320/390/1440: тайлсет одного физического размера на всех
вьюпортах (узкий просто показывает меньше мира — камера ведёт), плита не
сплющена как при прежнем дробном scale. `npm run build` без ошибок и
предупреждений о ненайденных ассетах, консоль чиста.

## 2026-08-27 — Задача 3, третья волна: пёс прыгает по-настоящему, край плиты

Ещё три отзыва сразу после предыдущей записи:

- **«пёс не прыгает как будто за Шутом»** — смена спрайта на `jump` сама
  по себе не читалась прыжком: пёс продолжал ровно скользить к цели по
  X и Y, только картинка менялась. Добавлена настоящая процедурная дуга
  (`dog.hopDelay` → `dog.hopT`, синус 0→π за `DOG_HOP_DURATION`, смещает
  `y` в `drawDog` через `dog.hopOffset`) — пёс подпрыгивает с небольшой
  задержкой реакции каждый раз, когда игрок уходит в `state==='air'`
  (вызов `scheduleDogHop()` в обоих местах, где это происходит: обычный
  прыжок и «сходит с края»). Щель под собой пёс по-прежнему не считает —
  просто подпрыгивает следом, синхронизировать с реальным временем полёта
  игрока не пытались, это по-прежнему процедурная заглушка, не физика.
- **«собаку на первом плане относительно Шута»** — поменяны местами
  вызовы `drawPlayer`/`drawDog`: пёс теперь рисуется вторым, поверх.
- **«на платформах Шут выходит за край»** — в этом же разговоре чуть
  раньше это уже пытались чинить, но фикс трогал только три статичных
  состояния ожидания (`wait_jump`/`wait_leap`/`charge`). Живой тест
  показал: то же самое видно уже ВО ВРЕМЯ ходьбы, на последних ~30px
  любой плиты — пользователь сообщил это отдельно как «на первой
  платформе», но это общий случай, просто первый, где он встречается.
  Переделано на плавный клэмп по
  фактическому краю ТЕКУЩЕЙ плиты (`standEdgeX`, из `platforms[idx]`,
  прокинут из `draw()` в `drawPlayer`): пока до края далеко — сдвига нет
  совсем, чем ближе — тем плавнее подъезжает, у самого края правый край
  спрайта просто не пересекает физическую границу плиты. Работает во всех
  четырёх состояниях на земле разом, без скачка при смене состояния.
  В воздухе (`air`/`fall`/`landed`) не клэмпим — там выход за плиту и есть
  смысл состояния.

Проверено покадровым тиком (`update()` дёргается вручную через временный
`__dTick`, а не через rAF, — реальным временем поймать точный момент
подхода к краю не вышло, тест-раннер слишком неровно троттлит кадры) на
390×844: за 2-3 кадра до края сдвига почти не видно, у самого края — спрайт
чисто на плите, пёс прыгает с заметной дугой и всегда поверх Шута.

## 2026-08-26 — BUILD-SPEC-03, задача 3: недостающие позы Шута

Сделано вне очереди по просьбе пользователя (задача 2 в списке спеки

Собраны и отправлены три контакт-листа (8 кадров прыжка, 8 направлений
и 8 поворотов парного падения).

**Пока ждали выбора, пользователь пересобрал ассеты Шута сам** и задал
новую раскладку поз целиком, другую, чем моя первая попытка:

- `idle` — 4 кадра дыхания из новой папки `idle fool/` (раньше был один
  кадр из `fool_rise.png`);
- `rise` (прыжок вверх) — `fool_rise.png` (раньше — «повышение», не
  используется в коде вовсе);
- `fall` (падение из обычного прыжка) — `fool_fall_side.png`,
  **зеркально** (исходник смотрит влево, сайдскроллеру нужно вправо);
  прежний источник (`fool_fall_front.png`) и моя ранняя прыжковая поза
  ушли из употребления;
- парное падение — то же `fall_pair/88x88/east.png`, без изменений.

Заодно пользователь переставил файлы в мастер-папке ассетов: `dog/` и
`fall_pair/` теперь лежат под `assets/the fool/` (не рядом), `fool_rope`
разделился на `_back`/`_side`, часть старых файлов (`Character Details

переставал находить дорогу и пса вовсе («нечего собирать»).

**В коде — не просто замена картинки, а деление обычного прыжка по фазе
дуги**: раньше на весь `state='air'` (короткий прыжок между плитами)
показывалась одна статичная поза; теперь — `rise`, пока `player.vy < 0`
(ещё поднимается), и `fall`, как только пошёл вниз. Читается ощутимо
живее, это расширение того, что просил пользователь, а не только замена
ассета. Финальный прыжок через пропасть (`state='fall'`/`'landed'`) — по
прежнему единый парный спрайт с псом, отдельно от этой пары.

**Технический довесок в `build-sprites.py`:** добавлена поддержка
`{'srcs': [...], 'flip': True}` вместо голого списка файлов — зеркалит
кадр по X перед нарезкой (`Image.FLIP_LEFT_RIGHT`), нужно было для
`fall_side`. Общий бокс солошных поз Шута пересчитался с 42×50 на
**44×48** — так и должно быть, раз источники сменились; парный спрайт
пса — `min_h=48` (было 50, подогнано под новую высоту соло-поз).

**Уборка:** исходники PixelLab (восемь `Character Details Rotations`,
`fool_running_jump`, оба размера `fall_pair`, необрезанные позы Шута,
неиспользуемый `oracle_sparks.png`) перенесены из `public/assets/` в
новую `art-source/` — Vite копирует `public/` в сборку целиком
независимо от того, ссылается ли на файл код, так что это была мёртвая
масса в бандле. `public/assets` полегчал с ~520 КБ до ~324 КБ. Внутри
`fool/strips/` (уже нарезанные полосы) `dog_jump_1f_18x14.png` остался,
хоть и не используется кодом — привязка к состоянию пса `'leap'` ушла
вместе с раздельной отрисовкой падения; сам файл не трогала, он маленький
и решение про него отдельное от этой задачи.

Проверено на 390×844: idle (цикл дыхания), rise, fall (зеркалом вправо) и
парное падение — каждая поза по отдельности, прямой подменой состояния и
`vy` через временный debug-хук (удалён перед коммитом). Консоль и

## 2026-08-24 — Мини-игра Шута: пропасть, финальный край, наклон вместо зарядки

Разбор ядра мини-игры. `BUILD-SPEC-03.md` переписан (задачи 4–7).

**Принцип сцены у последнего края:** не добавлять сигналы, а убирать
альтернативы. Игрок должен не догадаться, что нужно прыгнуть, а
обнаружить, что больше делать нечего — и что оставшийся жест он уже
делал десять раз. Ни одного слова подсказки в кадре.

**Решения:**

- **Удержание = наклон, а не зарядка.** Полоска `HOLD` отменена. Пока
  палец на экране, Шут наклоняется вперёд (поворот спрайта вокруг точки
  у ног, 0°→32°, 2.6 с до точки невозврата, последняя четверть
  медленнее). После невозврата тело уходит само. Отпустил раньше —
  выпрямился, стой сколько хочешь. Смысл сменился: игрок не копит силу
  прыжка, он **перестаёт удерживать себя**. Обратная связь живёт в мире:
  акцентная линия кромки укорачивается по мере наклона.
- **Пропасть видна всю дорогу.** Дышащий градиент под плитами с первого
  кадра: шесть ступеней палитры пустоты (`#161616`…`#2E2E2E`) с дизером
  Bayer 4×4 на границах, синус амплитудой 24 арт-px с периодом 7 с,
  смещение округляется до целого арт-пикселя. Никогда не светлее
  `#2E2E2E`. Параллакс 0.35. Пунктирный `drawFarRoad` убирается — его
  работу берут опоры и градиент. Финальный край перестаёт быть
  сюрпризом: пустота была под тобой с первой секунды.
- **Призрачное продолжение дороги осыпается** при подходе ближе 120px:
  дизер гаснет за 1.2 с, несколько пикселей сыплется вниз. Тихо, без
  наказания — вариант, на который игрок рассчитывал, просто перестал
  существовать.
- **Акцент — на кромке плиты, не в пропасти.** Загорается за 60px до
  края. Пропасть не красим оранжевым никогда: тронуть её нельзя, а
  `#EBA331` значит ровно «это можно тронуть».
- **Пёс НЕ прыгает первым.** Идея отклонена: прыгнувший первым пёс решает
  задачу за игрока и превращает решение в повторение за собакой, плюс
  риск прочтения «пёс погиб». Вместо этого — обгоняет, смотрит вниз,
  садится и оборачивается на игрока. Прыгает вместе с Шутом, парным
  спрайтом, уже в падении. Опционально — фальстарт (подошёл к краю,
  наклонился, вернулся).
- **Игра ждёт сколько угодно.** У последнего края нет таймаутов; знак
  удержания появляется только после 6 с полной неподвижности.
- **Внизу — та же самая дорога.** Из темноты проступают те же тайлы,
  идущие вправо. Ты не сорвался с пути, путь шёл вниз — ровно то, что
  говорит предсказание про землю под движущейся ногой. Ноль новых
  ассетов.
- **Высота плиты зафиксирована: 16 арт-пикселей** (32 экранных), по
  факту сгенерированного тайлсета. Расхождение 12/16 между кодом и
  `pixellab-plan.md` закрыто.

**PixelLab, побочный урок.** Двухтеррейновый режим (Lower/Upper Terrain)
для нашего бруса не работает — он делает карту из двух биомов. Рабочая

## 2026-08-23 — Размер карты при вылете, оракул: позиция и скорость входа

**Карта «прыгала» в размере при смене экрана 2→3** (баг из чата: «видно

Причина — размер карты в веере (`CARD_W_FRAC` 0.42, урезано в задаче 3,

Первая попытка исправить — интерполировать `w`/`h` карты к целевому

краем экрана — это нормально и было явно разрешено в том же разговоре
(«можешь наложить больше карты друг на друга, ничего страшного»).

обратно интерполирует только позицию и угол (размер везде одинаковый,
интерполировать нечего) — проще, чем промежуточный вариант. Углы/радиус
дуги (`FAN_ANGLE_TOTAL`, `FAN_RADIUS`, `ROW_GAP`) не потребовали
пересчёта: положение заднего ряда относительно шапки зависит только от
`CENTER_CARD_TOP_FRAC` и `ROW_GAP`, не от размера карты, так что зазор
с шапкой остался тем же на всех четырёх вьюпортах. Карты стали заметно
крупнее и плотнее перекрываются внутри ряда — соответствует референсу
«как настоящая колода веером», проверено на 320×568, 390×844 и 1440×860.

## 2026-08-23 — Рябь на картах веера + карта по центру на экранах 3–4

**Баг из чата: «работа сделана грязно, рябит, нечёткие пиксели».**
Причина — не в композиции, а в паре с техническим правилом CLAUDE.md
«`imageSmoothingEnabled = false` везде, всегда». `drawCard` в `deck.js`
рисует растровый PNG 224×384 (`back_side_card_final.png`) с двумя вещами
одновременно: произвольным поворотом (`ctx.rotate`, свой угол на дуге у
каждой карты) и произвольным, не кратным масштабом (карта — доля ширины
экрана, не целое число «арт-пикселей»). При жёстком nearest-neighbor это
и есть источник шума на тонкой штриховке (двойной контур, пунктирный
крест) — до сегодняшнего асеет-ревью тут стоял не PNG, а `ctx.strokeRect`
(вектор), а векторные примитивы canvas сглаживает сам, независимо от
`imageSmoothingEnabled` — поэтому артефакта не было видно раньше, он
появился именно с переходом на настоящий ассет карты.

**Правило не нарушено, а осознанно сужено**, вслух (как требует
CLAUDE.md при конфликте): `ctx.imageSmoothingEnabled = true` включается
только на время двух `drawImage` внутри `drawCard()` — `cardBack` и
`cardSelectFrame` — и автоматически откатывается обратно на `false` через
уже существующий `ctx.restore()` (значение — часть состояния контекста,
которое `save/restore` сохраняют и восстанавливают). Вне этой функции
правило «nearest-neighbor everywhere» не тронуто ни на пиксель — все
остальные спрайты игры (оракул, Шут, дорога, платформы) по-прежнему
рисуются без сглаживания, потому что там нет одновременно и поворота, и
дробного масштаба.

**Второе — карта по центру экрана на экранах 3 и 4** (правка в чате: «на
след экранах карту выбранную сделать чётко посередине экрана»). Раньше
`box.y = h × 0.364` — карта висела заметно выше геометрического центра,
ближе к шапке. Заменено на `(h − cardH) / 2` в трёх местах разом —
`draw.js`, `reveal.js`, и в `deck.js` — точке приземления вылетающей
карты (`FLY_DURATION`-анимация), чтобы при смене сцены 2→3 не появился
скачок по Y. Проверено на всех четырёх вьюпортах: заголовок и
«CLICK TO DRAW» / CTA-под-картой нигде не задеты, запас по вертикали
остаётся даже на самом низком экране (320×568).

тему:** `performance.now()` в этом инструменте — НЕ надёжный признак
свежей перезагрузки: он растёт даже сразу после `preview_stop` +
`tabs_close` + `preview_start` с нуля (наблюдалось 19–44 тысячи мс на
только что созданной вкладке). Настоящая проверка свежести — по
поведению игры (`window.gameCurrentScene()` сразу после загрузки должен
быть `question`), не по таймеру. Отдельно: `requestAnimationFrame` в
этой вкладке периодически troттлится настолько, что счётчик времени
сцены (`t`) не продвигается вообще даже за много секунд реального
ожидания (`computer.wait` И обычный `sleep` — оба) — единственное, что
надёжно «будит» рендер, это вызов `computer` (скриншот/клик). Для
проверки анимаций по конкретным моментам времени быстрее и надёжнее
временно завести сеттер (`window.__setT = v => { t = v; }`) прямо в
сцене, выставить нужное время и снять один скриншот — не пытаться
дождаться его через реальное время.

## 2026-08-19 — Экран 2: колода полукругом вместо плоского ряда

Отложенная с прошлой правки идея («колода не использует пространство
экрана... может закрутить полукругом и повернуть немного вбок») —
реализована. Раскладка была плоским рядом с едва заметной дугой по Y
(`FAN_ARC=4px` на карту); теперь настоящая полярная геометрия: точка-ось
ниже экрана (`FAN_RADIUS=780`, `FAN_ANGLE_TOTAL=62°`), центральная карта
смотрит точно вверх (самая высокая точка дуги), крайние расходятся в
стороны и поворачиваются на свой угол — как раскрытая веером колода в
руке. Карты неизбежно ниже по центру дуги дальше от центра (купол, не
плоский веер) — это и есть «полукруг», не баг геометрии.

- **Наведение** — приподнимает карту вдоль ЕЁ ЖЕ радиуса (от оси наружу),
  не по прямой Y: на повёрнутых крайних картах прямой Y-подъём выглядел
  бы перекошенным относительно угла самой карты.
- **`cardIndexAt`** — был ближайшим по X среди «домашних» слотов;
  на дуге этого недостаточно (у соседних карт X может быть близким при
  разных Y), переведён на 2D-расстояние до центра карты.
- **Каскад входа** — раньше летели по прямой из центра-сверху; теперь
  едут по радиусу от `FAN_RADIUS − CASCADE_DROP_HEIGHT` до `FAN_RADIUS`
  вдоль своего финального угла и ОДНОВРЕМЕННО разворачиваются из 0 в
  этот угол (`rotation = angle × easeProgress`) — читается как раскрытие
  веера, а не просто падение карт.
- **Вылет к экрану 3** — при выборе карта не просто летит по прямой к
  позиции экрана 3, но и выпрямляется по пути (`rotation = flyFrom.angle
  × (1 − p)`), к моменту приземления она уже не повёрнута — совпадает с
  ориентацией карты на экранах 3–4.

## 2026-08-19 — Единый уровень заголовков, центровка карты, размер спрайтов в Leap

Серия мелких, но по отдельности заметных правок в чате.

**Заголовок на одном уровне везде** — `ty = 70*scale` (уровень экрана 1)
теперь и на экранах 3 (`draw.js`) и 4 (`reveal.js`), которые раньше сидели

исключение:** сначала тоже переставила на 70, но по правке в чате
(«сделай как было») откатила обратно на 230 — это не часть связки «The
deck offers itself…» экранов 2–5, а самостоятельный финальный момент,
ниже по канону референсной PNG.

**Вспомогательный текст — тот же кегль, что на экране 1.** `CLICK TO
DRAW` на экране 3 был на роли `body` (16px), стал `menuOption` (22px),
как `PICK THE CARD…`, `SWIPE TO JUMP`, `CONTINUE`, `ONE MORE QUESTION`.
При этом поймала реальный баг: подпись после смены уровня заголовка стала
налезать на вторую строку «offers itself…» — отступ считался от
baseline второй строки плюс 9px, а не от первой строки на всю высоту
двух строк. Поправлено на ту же формулу, что уже была в `deck.js`/
`reveal.js`: `ty + 2×titleLH + 9×scale`. Semibold нигде не осталось —
`menuOption` и `body` не задают `weight`, значит всегда 400 (`setFont`).

**Карта — центровка номера и имени.** Оба стояли на `textBaseline:
'alphabetic'`, из-за чего визуально сидели выше геометрического центра
своих бирок (баг, а не мелочь — пойман по правке в чате дважды: «цифра
0 не посередине», «название чуть ниже»). Оба переведены на `textBaseline:
'middle'` на той же Y-точке (центр бирки), что и решает задачу разом для
обеих строк.

**Карта — фон интерьера `#111111`, не `#000000`.** Раньше подложка карты
заливалась чёрным телом объекта (то же решение, что у платформ дороги и
рубашки карты — «плита/тело темнее воздуха»), но по правке в чате для
самой карты фон должен сливаться с воздухом сцены, не выделяться. Это
целенаправленное отличие карты от дороги/рубашки, не откат общего
правила дизайн-системы.

**Спрайты в Leap были вдвое меньше нужного.** `PLAYER_W/H` и `DOG_W/H`
в `src/minigames/fool/leap.js` брались прямо из натуральных арт-px
размеров ассетов (42×50, 18×14) и умножались только на viewport `scale`
— без обязательного ×2 из правила сетки CLAUDE.md («1 арт-пиксель = 2
экранных»), которое уже было учтено в `PLATE_H` дороги (`platforms.js`),
но забыто для персонажа и пса при переносе в новый модуль. Правка в чате:
«спрайты очень маленькие — не соответствуют оригинальным размерам».
Константы теперь хранят уже удвоенные 84×100 / 36×28, дальше код без
изменений.

ниже плиты, с которой прыгнул, не долетев ни до одной другой — тебя
мягко возвращает на плиту-источник (позиция чуть перед её краем, состояние
`walk`, чтобы дальше сработала обычная логика прыжок/шаг, не жёстко
`wait_jump`, иначе на шаговой щели завис бы навсегда в ожидании свайпа,
который не нужен). Заодно чуть сузили сами щели (`GAP_JUMP` 64→52,
`GAP_JUMP_FAR` 80→64, `GAP_STEP` 36→32) — с респавном как настоящей
подстраховкой это можно позволить, играть чувствуется отзывчивее.

**Карта — типографика по Figma.** Номер и имя: Alagard Medium 30,
letter-spacing −4% (было — 24px без трекинга у имени, номер вообще на
0.6× меньше кегля). `core/text.js`: роль `cardName` — `size: 30, weight:
500, letterSpacing: -0.04`; `setFont()` конвертирует в
`ctx.letterSpacing` (px, не поддерживает %, считаем сами от кегля) и
всегда сбрасывает его на `0px` для ролей без трекинга, чтобы не
протекало между вызовами на одном `ctx`. Alagard — один статичный файл
без начертания Medium (index.html), `font-weight: 500` в коде оставлен
для точности документации, хотя браузер без синтеза всё равно отрисует
единственным доступным начертанием.

**Побочная находка про тестирование:** `tabs_close` + `preview_start`
НЕ даёт чистую перезагрузку страницы в этом инструменте — вкладка
переиспользуется без сброса JS-контекста (`performance.now()` продолжает
расти с прошлой сессии), из-за чего один раз залипший цикл игры на фоне
выглядел как «персонаж сам прошёл всю дорогу без ввода». Только явный
`window.location.reload()` действительно даёт чистое состояние — так и
тестировать дальше.

## 2026-08-11 — Развилка = вариант B; стек, хостинг и объём первой сборки

**Развилка у последнего края — вариант B (недосягаемое продолжение).**
Ветки нет: за пропастью видно, что дорога шла дальше, но допрыгнуть
нельзя, и она растворяется в дизеринге. Причина — вариант A (бесконечная
безопасная дорога) сильнее только если игрок всерьёз рассматривает уйти
по ней, а чтобы рассматривал, она должна выглядеть многообещающей, хотя
ничего не даёт; иначе это тот же B за неделю работы. Плюс риск потерять
тестера в первые 60 секунд первой карты.
**Место под ветку закладываем:** у последней плиты проектируется честный
выход вправо-вверх, пока не построенный.
**Ленточка на пересмотр:** на тестах смотреть ровно одну вещь — *свайпают
ли люди вверх, стоя у края.* Свайпают → они ищут другой путь, строим
**короткую** ветку (2–3 плиты, потом дорога видимо кончается), не
бесконечную. Не свайпают → B был прав.

**Объём первой сборки — вертикальный срез (§15).** Все 6 экранов оболочки
+ мини-игра Шута целиком + 3 предсказания (Fool × work/love/mental).
В веере видны 5 карт, выпадает всегда Шут. Остальные 4 мини-игры не
проектируются до тестов среза.

**Стек: vanilla JS модулями + Vite.** Без фреймворка. Причины: продукт —
6 экранов и canvas, React пришлось бы обслуживать ни за что; Vite даёт
живую перезагрузку и сборку в статику; отдельные файлы правятся Клод Кодом
надёжнее, чем один HTML (прототип уже 56 КБ / ~1300 строк в одном файле, и
правки начинают задевать соседний код). Прежний одностраничный формат
прототипа остаётся только у самого прототипа.

**Хостинг: GitHub Pages**, автодеплой по пушу в `main`. Тестер получает
обычную ссылку и открывает в браузере телефона — что и требовалось.
На бесплатном плане репозиторий должен быть публичным; если нужно скрыть,
альтернатива — Netlify с паролем.

**Подготовлено:** `tarot-journey/` — скелет проекта, `CLAUDE.md` (канон),
`BUILD-SPEC.md` (задание), `ASSETS.md` (чеклист), `src/data/cards.js`
(банк Шута написан).

## 2026-08-11 — The Fool: горизонтальная дорога вместо подъёма; удержание = решение

Крупная смена механики ведущей мини-игры. GDD §8.1a, §8.2, §8.3 переписаны.

**1. Подъём отменён, дорога идёт вправо и вниз.** Причины по убыванию
веса: (а) подъём ничего не репетирует — пять раз лезешь вверх, а финал
совсем другое действие; горизонтальная дорога репетирует финальный шаг
каждым шагом; (б) подъём — глагол усилия и цели, Шут ничего не
преодолевает; (в) обрыв перестаёт быть отдельной конструкцией и становится
просто концом дороги; (г) вместе с подъёмом отпадают верёвка, спуск и
пролёт камеры вверх — они существовали только чтобы вернуть Шута вниз.
Закрывает долг «~15 неинтерактивных секунд из 70», названный 2026-08-06.

**2. Правило дороги: вверх — свайпом, вниз — просто сходишь с края.**
Спуск не требует действия. Дорога 3–4 раза учит, что сойти с края
безопасно; на последнем краю Шут делает то же самое, и земли нет.
Черновой ритм на 8 плит — в §8.3.

**3. §8.1a переформулирован: удержание — не движение, а решение.**
Прежняя редакция (2026-08-06) делала удержание способом движения во всех
пяти картах. Отменено: удержание с зарядкой дальности — точностная
механика, точность мешает медитативности, игрок целится вместо того чтобы
проживать. Теперь движение у каждой карты своё (в Шуте — **свайп**, уже
реализован в прототипе как схема по умолчанию), а удержание встречается в
карте **ровно один раз** — в кульминации. Жест, которого игрок за всю
карту не делал, приходит в момент, который важен: смена движения тела =
смена смысла. Обучения не требует — заминка перед свайпом и есть
удержание. §8.2 пересобран под это (колонки «движение» / «удержание»).

**4. Развилка: безопасный путь — не опасный и не бесполезный, а
бесконечный.** Дорога вправо-вверх продолжается сколько угодно; вниз ведёт
один путь, и предсказание там. Указатель — пёс: не идёт на безопасную
дорогу, садится у последнего края и смотрит на игрока. Опасную
альтернативу отклонили — в no-fail игре опасность читается как ложь.
Дешёвая замена ветки: недосягаемое продолжение дороги за пропастью,
растворяющееся в дизеринге.

**5. Сетка:** фиксированный `STEP = 140` отменён, вертикальные дельты —
кратные тайлу (32 экранных px), чтобы фрейм-тайлы сходились по вертикали.

**Замечено попутно:** §8.3 в GDD всё это время содержал **старую тап-версию**
(«PRESS TO JUMP», «?»-боксы) — переписывание v5 от 2026-08-05/06 осталось
в логе и в прототипе, но в документ не попало. Теперь синхронизировано.

**Цена:** `fool_rise.png` и `fool_rope.png` уходят в стол; в прототипе
снимаются сцены `FLYUP`, `ROPEDROP` и вся логика верёвки/коридора.

**Не решено:** какая из двух версий развилки строится (полноценная
бесконечная дорога или недосягаемое продолжение).

**1. Шут — не одна из пяти карт, он ноль.** Единственный аркан вне
нумерованного ряда; классическое чтение всех 22 Старших — «путешествие
Шута»: он идёт сквозь Мага, Императрицу, Колесо, Башню до Мира и начинает
заново. То есть Шут не станция в колоде, а тот, кто по ней идёт — **это
игрок**. Следствие для продукта: маленькая фигурка Шута может появляться
во всех пяти мини-играх не как персонаж карты, а как аватар игрока; тогда
остальные четыре карты — места, куда он приходит. Сквозная нить почти
бесплатно, спрайт уже нарисован. *(В MVP не обязательно, но записано.)*

**2. Карта изображает момент ДО, а не падение.** На классическом
изображении он ещё не шагнул. Значит дольше всего игра должна держать
именно край. Полоска удержания удлинена с 1,4 до ~2,6 сек, причём
последняя четверть заполняется медленнее остальных; пока она идёт, воздух
и гул стихают до тишины, пёс прижимается к ноге.

**3. Шут смотрит не вниз, а вверх** — он не храбрый, его внимание просто
в другом месте. Из этого была собрана пауза перед падением: камера уходила
вверх, вверху проступало бледное дизеринговое свечение. **ОТКАЧЕНО
2026-08-06 после просмотра — выглядело плохо.** Идея верна по смыслу, но в
таком исполнении не работает; если возвращаться, то не подъёмом камеры и не
дизеринговым пятном. Сейчас полоска заполняется — и он шагает сразу.

**4. Удержание — сигнатурный жест ВСЕХ пяти карт.** Записано в GDD §8.1a
и §8.2 переписан: отличается не жест, а что удержание делает и что значит
отпустить. Fool — шагнуть; Magician — направить силу; Empress — оставить
выросшее; Wheel — отпустить колесо; Tower — дать упасть. Обоснование:
мобильные веб-игры держатся на одном трансформирующемся глаголе, а вся
медитативность живёт в том, что происходит, **пока ты держишь**.

**Открытый долг:** мини-игра стала на ~15 секунд неинтерактивной из 70
(пёс, узелок, взгляд в пропасть, небо, приземление). Для медитативной вещи
допустимо, но названо: середина авторская, сыграна только концовка.

## 2026-08-05 — Переработка мини-игры The Fool: GDD §8.3 переписан

Алиса показала 6 финальных экранов и переописала мини-игру. Старая спека
§8.3 («одна кнопка, движение только вперёд, земля появляется под ногой»)
**отменена**. Новая схема:

- **Уровень:** платформы вверх, наверху платформы кончаются. Пропасть с
  пиксельным туманом — внизу, под стартовой площадкой.
- **Разворот:** доходишь до верха → камера отбирается у игрока, уходит
  вверх мимо пустоты, потом проезжает весь уровень вниз до тумана и
  возвращается. Ни слова текста. Идея «опасности сверху» рассмотрена и
  **отклонена** — погоня ломает медитативный тон (линза Unification).
- **Финал:** удержание у края → Шут наклоняется, туман тянется вверх, звук
  растёт → отпускание = шаг в пустоту → предсказание.
- **Падение:** упасть можно, но трудно (платформы щедрые). Туман **всегда**
  мягко возвращает на стартовую площадку — и до разворота, и после.
  Единственное, что уводит в предсказание, — сознательное удержание у края.
  Случайное падение не может «проскочить» финал, а поскольку туман выносит
  ровно туда, куда игрок и шёл, спуск становится быстрым, а не наказанием.
- **Тюнинг прыжка (принцип):** голый тап поднимает ~85px, вертикальный шаг
  между платформами — 110px. Значит подъём всегда стоит удержания, а спуск
  получается сам собой тем же жестом. Один глагол в обе стороны.
- **Управление:** выбрано **тап по половине экрана = прыжок в ту сторону,
  удержание = заряд дуги**. Ходьбы нет: Шут только прыгает. Это возвращает
  принцип «один жест = глагол карты» (*leap*) и делает финальное удержание
  той же механикой на пределе, а не отдельной. Экранные ◄ ► + JUMP,
  рогатка и свайп реализованы в прототипе как альтернативы для теста.

**Хаптик — техническое ограничение (важно, влияет и на The Tower):**
`navigator.vibrate` в Safari на iOS не реализован никогда. Единственный
рабочий хак — скрытый `<input type=checkbox switch>` + `<label>` с
программным `click()` — работал с iOS 17.4 по 26.4, Apple залатала в 26.5.
Вывод: **тактильность строим на Web Audio** (низкочастотные импульсы
40–60 мс с жёсткой атакой) + микросдвиг кадра на 1px; вибрация — только
необязательная надстройка. Хаптик-ядро The Tower (§8.2), где весь смысл
release нёс обрыв вибрации, придётся пересобрать на звуке.

**Правка 2026-08-06 (спуск + управление):**
- Управление по итогам теста руками: **свайп** (проверено на телефоне,
  оказался удобнее половин экрана). Вектор флика раскладывается на две оси:
  насколько вверх — высота, насколько вбок — дальность. Голый тап = самый
  маленький прыжок, им же и спускаешься. Финальный шаг с обрыва остаётся
  **удержанием** — единственный момент, где игра просит другой жест.
- **Финал: удержание с индикатором-заполнением, а не «отпустил — прыгнул».**
  Держишь — линия-полоска заполняется оранжевым за 1.4 сек, и когда полна,
  Шут шагает сам. Отпустил раньше — полоска сливается назад, он выпрямляется.
  Так решение становится явным и его нельзя отменить в последний момент.
- **Спуск = верёвка, и она ПОЯВЛЯЕТСЯ** (решено 2026-08-06). Принцип: быстрый
  путь вниз не должен существовать до того, как игрок понял, что наверх
  нельзя. Верёвка падает сверху — из той самой пустоты, которую только что
  показала камера, — разматывается за 1.1 сек и ведёт **не в туман, а на
  стартовую площадку, в сорока пикселях от обрыва**. Вариант «шахта с
  оранжевым пунктиром» отклонён: непонятно и существует с самого начала.
- **Уровень зеркально перевёрнут:** обрыв теперь у ЛЕВОГО края стартовой
  площадки. Иначе не собирался чистый вертикальный коридор для верёвки,
  который одновременно свободен от платформ и проходит над площадкой.
  Заодно ближе к мокапу, где Шут стоит слева. Колонки платформ: левая
  x 20–150, правая x 230–410, коридор между ними x 154–226. Нахождение в
  коридоре = хват верёвки, отдельного жеста нет.
- Портал отклонён (чужой словарь + решает несуществующую проблему).
  Молнии отклонены (иконография Башни + возвращают угрозу).
- Туман во время подъёма возвращает на **последнюю достигнутую платформу**,
  а не на старт; на стартовую площадку — только после разворота.

**Правка 2026-08-06 (вторая): разворот через пса, узелок, падение с камерой**

- **Разворот показывает ПЁС, а не камера.** Демонстрация вместо указания:
  пёс обгоняет Шута на верхней площадке, добегает до края, садится,
  смотрит вниз, оборачивается на игрока — и прыгает. Камера следует за
  ним, он приземляется внизу целым и ждёт. Игрок не получает инструкцию,
  он видит, что кто-то уже это сделал и не разбился. Пролёт камеры вверх
  сокращён с 8 сек до 3,2 — он теперь только говорит «выше ничего нет»,
  а «вниз можно» говорит пёс.
- **Верёвка = его собственный узелок.** Шут развязывает узелок с палки, и
  тот разматывается в верёвку. Вниз он приходит **с пустыми руками** — а
  через двадцать секунд получит текст, который начинается с «with empty
  pockets». Предмет перестал быть реквизитом уровня и стал частью
  персонажа; спуск стал платой, а не лифтом.
- **Спуск по верёвке — на УДЕРЖАНИИ.** Держишь — едет, отпустил — замер.
  Сделано специально, чтобы к моменту финала жест «держать» уже был в
  пальцах: одна механика обучает другой (линза Elegance).
- **Финал — прыжок вдвоём с псом**, камера летит вместе с ними, мимо
  проносится дизеринг, гул пропасти обрывается в тишину за полсекунды до
  конца, и **белая линия земли проступает в момент касания** — карта
  наконец выполняет собственную строчку «the ground will be there when
  your foot lands». Без молний (иконография Башни).
- **Ориентация уровня возвращена:** стартовая площадка слева (x 20–250),
  обрыв за её правым краем. Колонны x 20–186 и x 254–414, коридор для
  верёвки между ними x 190–250, ровно над площадкой. Шаг между
  платформами поднят со 110 до 140 — стало просторнее для прыжка.
- **Пропасть:** туман убран полностью. Чернота, и только у самого дна —
  ступенчатый дизеринговый градиент `#161616`→`#2E2E2E`. Дно опущено на
  270px ниже площадки, чтобы под ней был воздух.
- **Сетка 2px зафиксирована:** 1 пиксель арта = 2 пикселя экрана. Все
  координаты чётные, толщины линий 2/4/6 (было 1/3), спрайт рисуется
  ровно 72×88 без пересэмплинга, ячейка дизеринга 2px.

**Правка 2026-08-06 (третья): вес переживания вместо длины подъёма**

Разбор по линзе Essential Experience: игрок должен унести «я отпустил», а
runtime обслуживал «я забрался» — две трети времени на подъём, пятая часть
на отпускание. Кривая интереса плоская 40 секунд. Чинится не сложностью:
проблема не в том, что подъём лёгкий, а в том, что он **ничего не стоит**,
и потому открытие, что он был не туда, тоже ничего не стоит.

- **Подъём срезан с 7 платформ до 5.**
- **Платформы сужаются к верху, но только с ВНЕШНЕГО края** — внутренние
  губы стоят на месте (186 слева, 254 справа), так что перелёт никогда не
  становится труднее, просто мира остаётся всё меньше.
- **Виньетка смыкается с высотой** (дизеринг чёрным по краям кадра).
- **Узелок звучит.** Тихий деревянный стук на каждом прыжке всю дорогу
  вверх. Шут его развязывает — и звук исчезает; остаток игры слышно
  отсутствие, которое нельзя назвать. Подъём получает цену, расставание —
  вес.
- **Первый вдох:** 2 секунды, где он просто стоит и ввод не принимается,
  потом проявляется подсказка. Медитативная вещь не начинается с работы.
- **Предсказание больше не отдельный экран.** Затемнение заменено на скрим
  0.78 поверх той же сцены; камера отводит фигуры вниз кадра, текст
  проступает в пустоте над ними. Награда приходит туда, где заработана.

- **Пролёт камеры вниз после спуска.** Как только Шут сходит с верёвки на
  стартовую площадку, камера уезжает вниз вдоль пропасти — площадка
  оказывается у самой верхней кромки кадра, а остальное занимает
  дизеринговый градиент, — держит момент и возвращается. Гул нарастает,
  пока смотришь. Ни слова: перед тем как игру попросят шагнуть, ему дают
  увидеть, куда.
- **`HOLD TO LEAP` → `HOLD TO JUMP`.** «Leap» читалось непонятно; глагол
  карты остаётся *leap* в документах, но в интерфейсе — простое `JUMP`,
  как и в остальном копирайте (`PRESS TO JUMP`, `SWIPE TO JUMP`).

**Технические баги, найденные при просмотре цикла:**
- *Дрожание платформ* — не рендер, а камера: хранится дробным числом, всё
  рисование снапится на 2px, при её сползании мир мигал между двумя
  положениями. Камера снапится на сетку перед отрисовкой.
- *Падение уносило вправо за кадр* — боковая скорость не гасла (0.995 за
  кадр) и камера не следит по X. Теперь скорость гаснет за 0.5 сек и его
  сносит обратно к центру.
- *Падение было быстрым и никаким* — гравитация втрое ниже, потолок
  скорости ниже, длительность 5 сек вместо 3, slow-motion на секунду в
  момент шага, три слоя пыли с параллаксом (без него падение не читается).
- *Звук* — удары вдвое тише, разброс по высоте у шагов; добавлен воздушный
  слой (коричневый шум через lowpass), который с высотой становится тоньше
  и тише, нарастает в падении и обрывается в тишину перед землёй.

**Прототип:** `fool-minigame-prototype.html` — один файл, vanilla + Canvas,
430×932, 4 схемы управления с переключателем, туман (Bayer 4×4, 3 слоя),
пролёт камеры, финальное удержание, посимвольная печать предсказания.
Проверен headless-прогоном: уровень проходится за 8 прыжков, все переходы
состояний (PLAY → FLYUP → LEAP → FALL → READING → restart) работают.

**Разбор:** `lens-review-02-fool-minigame.md` — 7 линз Шелла (Toy, Skill,
Physical Interface, Juiciness, Indirect Control, Moments, Atmosphere).

**Решения игрока (подтверждены в этой сессии):**

3. **Предсказание = СТАТИЧНЫЙ банк текста** (без вызовов ИИ в рантайме).
   Это разрешает старый конфликт «живой ИИ vs банк» → победил банк.
   Печать посимвольно остаётся.
4. **Текст предсказания = карта × категория.** 5 карт × 3 категории = 15

5. **Игра ТОЛЬКО НА АНГЛИЙСКОМ.** Причина — дисплейный шрифт Alagard
   латинский. Двуязычность RU/EN и весь каркас i18n (был раздел 12 v3.0)
   уходят из активного плана в backlog.
6. **Дисплейный шрифт — Alagard** (пиксельный блэклеттер), заменяет

7. **Оракул — Future Teller, не VAEL.** Подтверждено окончательно: имя

## 2026-07-12 — Пивот: пре-рекорд банк + мини-игры (интервью)

Крупная развилка. Отход от живого ИИ в реальном времени к статичному,
заранее сгенерированному контенту, плюс возврат мини-игр из v1.0.
На основе этого решения переписан GDD → v3.0.

**Решения игрока:**

1. **Реплики VAEL — статичный банк текста.** ИИ помогает написать пул
   реплик ЗАРАНЕЕ, тексты хранятся статично (JSON/код). В самой игре —
   никаких вызовов API, только подстановка нужного текста. Печать
   посимвольно остаётся.
2. **Причины пивота:** контроль качества реплик, уход от API-ключа/прокси/
   рисков утечки ключа на клиенте, стоимость токенов за каждый визит.
3. **Мини-игра под каждый аркан (unique).** Возрождает таблицу мини-игр
   из GM Doc v1.0 (раздел 5). Каждая карта = отдельная короткая механика,
   отражающая архетип.
4. **Мини-игра заменяет экран медитативного задания.** Мини-игра И ЕСТЬ
   новое, интерактивное медитативное задание. Старый текстовый экран 6.6
   убирается.
5. **Предсказание = награда** за прохождение мини-игры. Смещает вес и
   внимание на предсказание.
6. **Все экраны сохраняются.** Мини-игра встраивается в момент раскрытия
   карты: после тасовки и переворота рубашка карты исчезает, остаётся
   внутренняя картинка (как правило — персонаж), поверх появляется UI
   мини-игры.

**Мои рекомендации (принято как решение, легко откатить):**

7. **Итог мини-игры НЕ ветвит текст в MVP.** Проиграть нельзя — механика
   медитативная, без фейл-стейта (держит тон «без спешки и напряжения»,
   не размножает банк в разы). Один текст предсказания на карту × тему.
   Post-MVP: лёгкий нюанс — одна финальная строка варьируется по мягкому
   качественному итогу («быстро нашёл свет» / «долго шёл в темноте»),
   без ветвления всего текста.
8. **Экран диалога → пре-рекорд с выбором.** Живой ИИ уходит, экран
   остаётся. Меню из 2–3 заготовленных вопросов, на каждый записан ответ
   VAEL. Сохраняет экран и голос персонажа без API.
