# PIXELLAB — что умеет, что это стоит, чем пользоваться нам

Разбор документации `pixellab.ai/docs` + список MCP-инструментов
(`api.pixellab.ai/mcp/docs`), 2026-09-11.

Отменяет часть `design-system/pixellab-plan.md` (папка-архив): там описан
только тайлсетный сценарий и нет ни цен, ни ограничений ракурса, ни MCP.

---

## 1. Главное, что меняет нашу работу

**1. Ракурс.** Инструмент, которым генерились карты (`create_1_direction_object`,
он же экран с «Generates N frames at Mpx»), принимает только два значения вида:
**`top-down`** и **`sidescroller`**. Значения `side` в нём **нет вообще** —
поэтому всю сессию результат приезжал как `low top-down`, сколько бы мы ни
писали «side view» в промпте. Для вида сбоку в этом инструменте нужен
**`sidescroller`**.

Значение `side` есть у других инструментов: `create_image_pixflux`,
`create_image_pixen`, `create_map_object`, `create_character`.

**2. Цена.** Разброс двадцатикратный:

| инструмент | цена | время |
|---|---|---|
| `create_image_pixflux` | **1 генерация** | 10–40 с |
| `create_image_pixen` | 1 генерация | 10–40 с |
| `unzoom_image` | 0.1 | <1 с |
| `correct_pixelart` | 0.1 | 20–60 с |
| `reduce_colors` | 0.1 | ~1 с |
| `create_1_direction_object` | **20–40 генераций** | 30–90 с |
| `create_image_pro` | 20–40 | 1–10 мин |
| `edit_image` / `inpaint_image` | 20–40 | 30–90 с |
| `create_character` (standard) | ~1 | 2–5 мин |
| `create_character` (pro) | 20–40 | 2–5 мин |

Мы весь день итерировали на инструменте за 20–40 генераций. Черновые заходы
надо гонять на `pixflux` за одну.

**Размен честный:** у `pixflux` **нет референса стиля** (есть `init_image` и
`color_image`, но не style). Стиль держат только дорогие инструменты. Отсюда
рабочая схема ниже.

**3. Число кадров задаётся размером**, а не отдельной настройкой. Это не
«режим набора предметов», как я сперва решил:

| размер | кадров | референсов стиля |
|---|---|---|
| ≤32px | 64 | до 64 |
| 43–64px | 16 | до 16 |
| 86–128px | 4 | до 4 |
| 171–256px+ | **1** | **1** |

**4. Палитру можно отдать картинкой.** `create_image_pixflux` принимает
`color_image` — PNG с нужными цветами. То есть `tarot-journey.hex` можно
скормить прямо в генерацию, а не чинить палитру потом.

## 2. Рабочая схема под наши карты

1. **Черновики композиции** — `create_image_pixflux`, `view: side`,
   `no_background: true`, `color_image` = полоса нашей палитры. Одна
   генерация за попытку, итерируем сколько нужно.
2. **Финальный кадр в едином стиле** — `create_1_direction_object` с
   `view: sidescroller` и портретом Шута в `style_images`, размер 171–256
   (тогда ровно один кадр и один референс). Один раз, 20–40 генераций.
3. **Приведение к канону** — `design-system/card-art.py` локально и бесплатно:
   снятие нативного масштаба, инверсия, альфа 0/255, снап в палитру, кроп,
   ×2 или ×3. Делает то же, что `unzoom_image` + `correct_pixelart` +
   `reduce_colors`, но точнее (ровно наши хексы) и без расхода генераций.

## 3. MCP-сервер

Есть, 107 инструментов. Подключается к Claude Code одной командой:

```
claude mcp add pixellab https://api.pixellab.ai/mcp -t http -H "Authorization: Bearer ТОКЕН"
```

Токен берётся на `pixellab.ai` после входа. **Команду выполняет человек сам в
своём терминале** — значение токена не пересылается в переписке.

Что это даёт: генерация идёт из сессии, без ручных прогонов и пересылки PNG;
результат сразу проходит `card-art.py` и ложится в `public/assets/`.

Клиенты: Claude Code, Cursor, VS Code, Zed, Windsurf, Claude Desktop и прочие
MCP-совместимые.

Скачивание готового: `/mcp/characters/{id}/download` — без авторизации, UUID
и есть ключ доступа.

## 4. Инструменты, которые нам понадобятся дальше

**Под мини-игры (BUILD-SPEC-06 и далее):**

- `create_sidescroller_tileset` — тайлсет платформера, 16 или 32 px, 2–3
  генерации. **Это путь к башне секциями** (§12 BUILD-SPEC-06): тело,
  бесшовное по вертикали, собирается тайлами.
- `animate_image` — анимация из кадра, 4–16 кадров (чётное), вход ≤256×256,
  бюджет `ширина × высота × кадров ≤ 524288`. Первый кадр всегда сохраняется
  как есть.
- `animate_image_pixminimax` — 4–40 кадров, 12 генераций за 40-кадровый ролик.
- `create_map_object` — отдельный предмет, `view: side`, 1–2 генерации.
  Под корону и обломки.

**Под интерфейс:**

- `create_ui_asset` — 192–688 px, принимает `style_image`. Теоретически может
  дать рамку карты, но у нас она уже есть и общая для всех карт.
- `create_font` — 8/16/32/64 px на глиф. Не нужно, у нас Alagard.

**Чистка:**

- `unzoom_image` — снимает целочисленный апскейл (0.1 генерации).
- `correct_pixelart` — чистит кайму антиалиасинга (0.1).
- `reduce_colors` — квантование в палитру, дизер none/2x2/4x4/8x8 (0.1).

Все три дублируются нашим `card-art.py` и бесплатны локально.

## 5. Ограничения, о которые можно удариться

| что | предел |
|---|---|
| `create_image_pixflux` холст | площадь ≤200×200 free, ≤320×320 tier 1–2 |
| `create_image_pro` холст | до 512×512, неквадрат до 688×384 |
| `reduce_colors` вход | ≤512×512 |

| `create_8_direction_object` кадр | ≤168×168 |
| референс для `create_character` | ≤256×256 |
| кадров в анимации | 4–16, чётное |

## 6. Ключи настроек (одинаковые почти везде)

- **`view`** — `side` · `low top-down` · `high top-down` · `oblique`.
  У `create_1_direction_object` только `top-down` · `sidescroller`.
- **`outline`** — `single color black outline` · `single color outline` ·
  `selective outline` · `lineless`. Нам — **`single color outline`** (контур
  белый, не чёрный).
- **`shading`** — `flat` · `basic` · `medium` · `detailed`. Нам — **`flat`**.
- **`detail`** — `low` · `medium` · `high`. Для карточных портретов —
  **`low`**: беда была в дробности, а не в размере пикселя.
- **`text_guidance_scale`** — 1.0–20.0, по умолчанию 8.0. Выше — строже по
  тексту, но растут артефакты.
- **`init_image_strength`** — 0–500. 0–300 грубая подсказка по цвету,
  300–400 форма и цвет, 400–600 вариации существующего, 600–900 доводка.
- **`no_background`** — прозрачный фон.
- **`seed`** — 0 = случайно. Понравившийся записывать и держать на серию.

## 7. Права

Коммерческое использование разрешено. Единственное условие — не обучать на
сгенерированном новые модели. PixelLab не хранит входные и выходные картинки
и не учится на них.
