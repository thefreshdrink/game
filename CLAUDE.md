# TAROT JOURNEY — правила проекта

Медитативный веб-ритуал. Игрок приходит к оракулу Future Teller, выбирает
категорию вопроса, вытягивает карту таро, проживает её смысл через короткую
мини-игру и получает предсказание как награду.

Сейчас строится **вертикальный срез: одна карта (The Fool) целиком** —
вход, мини-игра, предсказание. Задание — `BUILD-SPEC.md`. Полный замысел —
`docs/tarot-gdd-v2.md` (редакция v4.0), история решений —
`docs/decisions-log.md`, стиль — `docs/design-system.md`, канон по UI —
шесть PNG в `docs/interfaces/`.

## Приоритет источников при конфликте

1. `BUILD-SPEC.md` — что строим сейчас
2. `docs/decisions-log.md` — что и почему решено (свежие записи сверху)
3. `docs/tarot-gdd-v2.md` — замысел
4. `docs/interfaces/*.png` — канон по флоу и UI-копирайту
5. `docs/design-system.md` — как это нарисовано

Если находишь противоречие между документами — **скажи об этом вслух, не
сглаживай молча.**

## Канон, который нельзя нарушать

- Оракула зовут **Future Teller**. Имени VAEL не существует — если увидишь
  его в старом коде, это ошибка.
- Вход — **3 категории: WORK / LOVE / MENTAL.** Не 6 тем.
- Предсказания — **статичный банк** в `src/data/cards.js`. **В рантайме
  никаких вызовов ИИ, никаких сетевых запросов, никаких API-ключей.**
  Только подстановка по ключу `card.reading[category]`.
- Игра **только на английском.** Никакого русского в интерфейсе и текстах.
  Комментарии в коде — можно по-русски.
- **Проиграть нельзя.** Нет смертей, нет таймеров, нет очков, нет экрана
  проигрыша, нет знака успеха после прыжка. Темп задаёт игрок — в мини-игре
  «Leap» это буквально: ходьба ручная (держишь палец — идёт), автопрохода
  нет (правка в чате 2026-08-28). **Упасть можно** — сойти с края или не
  дотянуть прыжок; падение возвращает на начало текущей плиты (теряешь
  отрезок, не всю игру). Это не «проигрыш»: ни экрана, ни счёта, ретрая
  сколько угодно. «Промахнуться нельзя» из старых комментариев `platforms.js`
  — **устарело**: невозможную щель прыгнуть нельзя, но обычную — можно
  завалить вялым свайпом.
- Флоу — ровно **6 экранов**. Новых не добавляем (§6.7 GDD).

## Визуал

Палитра — только эти цвета (`docs/design-system.md`, `tarot-journey.hex`):

| роль | hex |
|---|---|
| фон / воздух | `#111111` |
| тело объекта (темнее воздуха) | `#000000` |
| главный контур | `#FFFFFF` |
| вторая линия двойного контура | `#B8B8B8` |
| дальняя деталь | `#4A4A4A` |
| текстура, пунктир | `#808080` |
| градации пустоты | `#161616 1C1C1C 212121 252525 2A2A2A 2E2E2E` |
| **акцент** | `#EBA331` |

**`#EBA331` означает ровно одно: «это можно тронуть».** Ничем другим
оранжевый не красим — ни платформами, ни туманом, ни декором. Пурпур
`#DB53FD` / `#994AFF` из старых редакций GDD §10 и красный `#CC0000` из
прототипа v2.1 — **устарели.**

Шрифты: **Alagard** — дисплейный (заголовки, имена карт), **Pixelify
Sans** — текстовый. Больше никаких.

## Сетка пиксель-арта

- **1 арт-пиксель = 2 экранных.** Все координаты и размеры — чётные.
- **Вертикальные дельты уровня — кратные 32 экранным** (16 арт-пикселей).
  Ширины платформ — кратные 32 экранным: дорога собирается целыми тайлами
  16×16 арт-px (торец + N×серединка + торец), см. `ASSETS.md`. Высота
  плиты — **32 экранных px** (16 арт-px, ячейка тайла целиком; решение
  2026-08-28 по переписанной `BUILD-SPEC-03` задача 2 — было 24).
- `ctx.imageSmoothingEnabled = false` везде, всегда.
- Спрайты рисуются только по целым координатам (`Math.round` перед
  `drawImage`), иначе появится размытая полоска.
- Графический язык — три блока: двойная линия (белая 2px + серая 1px под
  ней), угловая скоба вместо замкнутого прямоугольника, пунктир с шагом
  2–3. Что не собирается из них — выпадает из стиля.

## Голос Future Teller

Низкий, поэтичный, приземлённый. Второе лицо («you»). Короткие
предложения. Без буллетов, markdown и эмодзи. Никогда не советует прямо,
не выходит из роли, не упоминает, что он ИИ.

Тексты пишутся **вне игры** и вычитываются вручную. Не генерируй
предсказания в коде и не придумывай новые на ходу — если нужен текст,
которого нет в банке, скажи об этом.

## Технические правила

- Vanilla JS, ES-модули, `<canvas>`. Фреймворка нет и не заводим.
- Один модуль — одна ответственность. Файл больше ~400 строк — повод
  разделить. Мы ушли от одностраничного прототипа именно из-за этого.
- Никаких зависимостей в рантайме. Только Vite в devDependencies.
- Не подключай CDN-скрипты и внешние сервисы.
- Прототип `../fool-minigame-prototype.html` в корне старой папки — не
  импортируй его, но подсматривай физику, звук и тайминги: там уже
  подобраны рабочие значения.
- Тактильность — через Web Audio. `navigator.vibrate` в iOS Safari **не
  работает**, на него нельзя опираться.
- Звук стартует только после первого касания (политика автоплея).

## Проверка перед тем, как сказать «готово»

- `npm run build` проходит без ошибок и предупреждений о ненайденных
  ассетах
- открывается на телефоне в портрете, ничего не обрезано, страница не
  скроллится и не зумится от свайпа
- в консоли пусто
- цвета — только из таблицы выше; поиск по `#` в коде это подтверждает
- проходится весь цикл: вопрос → карта → мини-игра → предсказание →
  ONE MORE QUESTION → снова вопрос
